# 설비 예지보전 (Predictive Maintenance) — 센서 파이프라인부터 대시보드까지

**CNC 밀링 설비의 센서 데이터를 수집·정제하고, 30분 내 고장을 예측합니다.**
수집 파이프라인(GitHub Actions 자동화)부터 대시보드 배포까지 전 구간을 직접 구성했습니다.

🔗 **[대시보드 바로가기](<본인 Streamlit 앱 URL>)** · 📄 **[분석 리포트](reports/analysis_report.md)**

## 30초 요약

| 항목 | 내용 |
|---|---|
| **문제** | 설비 고장을 **사후 감지**가 아니라 **30분 전 예지** — 계획 정비로 라인 정지를 막는다 |
| **데이터** | ① 물리 기반 시뮬레이터(자체 제작, 3대×14일, 55,591행) ② UCI AI4I 2020(10,000행) ③ UCI SECOM(1,567행×590센서) |
| **방법** | 수집(스케줄러→SQLite) → 정제(9단계) → 피처 100개 → RandomForest → **시간순 split** → **비용 기반 임계값** |
| **결과** | 시뮬레이터 **PR-AUC 0.759**(기준선 0.237) / AI4I **PR-AUC 0.897**(기준선 0.034) / SECOM **PR-AUC 0.083**(기준선 0.061, *실패*) |
| **핵심 발견** | 랜덤 split을 쓰면 PR-AUC가 **0.982로 부풀려집니다**. 같은 데이터·같은 모델인데 **22.6% 차이**입니다 |
| **한계** | 시뮬레이터는 합성 데이터, 비용 가정은 추정치, SECOM은 예측 실패(원인 규명함) |

## 왜 이 주제인가

제조 데이터 분석은 **채용 시장이 따로 있습니다.** 삼성전자·SK하이닉스·LG전자·포스코·현대차 등이
공정/설비 데이터 인력을 지속적으로 뽑습니다. 그런데 포트폴리오는 대부분 웹/커머스 데이터입니다.

그리고 제조 데이터에는 다른 도메인에 없는 함정이 있습니다.
이 프로젝트는 **그 함정들을 실측으로 보여주는 것**을 목표로 했습니다.

## 핵심 결과 3가지

### 1. 정확도 96.6%짜리 쓰레기 모델

AI4I 데이터의 고장률은 3.39%입니다. **"전부 정상"이라고만 답해도 정확도 96.6%** 입니다.
재현율은 0.0000이고요.

| 모델 | 정확도 | 재현율 | PR-AUC |
|---|---|---|---|
| 무조건 "정상" | **0.9660** | 0.0000 | 0.0340 |
| 랜덤포레스트 | 0.9824 | 0.5765 | 0.7886 |
| 랜덤포레스트 + 도메인 파생변수 | 0.9928 | 0.8235 | **0.8966** |

→ 정확도는 세 모델을 구분하지 못합니다. **PR-AUC와 기준선(=고장률) 대비로 봐야 합니다.**

### 2. ★ 시간 누수 — 랜덤 split이 만든 허수

같은 데이터, 같은 모델, 같은 하이퍼파라미터. **split 방식만** 바꿨습니다.

| split | ROC-AUC | PR-AUC | F1@0.5 |
|---|---|---|---|
| 랜덤 split (흔한 실수) | 0.9954 | **0.9820** | 0.9338 |
| 시간순 split (올바름) | 0.8953 | **0.7605** | 0.6769 |

**PR-AUC 22.6% 하락.** 원인은 자기상관입니다.
랜덤 split에서 test 행과 가장 가까운 train 행의 시간 거리는 **중앙값 0분** — 바로 옆자리입니다.
예측 라벨의 미래 창이 30분이니 창이 통째로 겹칩니다.

> 반전: **AI4I에서는 랜덤 split을 써도 거의 차이가 없습니다**(lag-1 자기상관 0.005).
> "시계열이면 무조건 시간순 split"이 아니라 **"시간적 의존성이 있으면 시간순 split"** 이 정확한 원칙입니다.

### 3. 임계값 0.5는 근거 없는 관행

고장 놓침 800만원, 헛점검 30만원(가정)일 때 총비용:

| 임계값 | 재현율 | 정밀도 | 총비용 |
|---|---|---|---|
| 0.50 (관행) | 0.824 | 0.959 | 12,090만원 |
| **0.06 (비용 최소)** | 0.929 | 0.444 | **7,770만원** |

→ **35.7% 절감.** F1이 최대인 지점(0.435)과 비용이 최소인 지점(0.06)은 다릅니다.

## 프로젝트 구조

```

├── README.md
├── requirements.txt
├── .github/workflows/collect.yml   # 매일 자동 수집 (무료)
├── src/
│   ├── simulator.py       # 물리 기반 센서 생성 + 현장급 오염 주입
│   ├── collector.py       # 주기 수집 → CSV + SQLite
│   ├── db.py              # SQLite 스키마 (UNIQUE로 중복 방어)
│   ├── build_db.py        # CSV → DB 재생성 (재현성)
│   ├── clean.py           # 9단계 정제 파이프라인
│   ├── features.py        # 파생변수 + 롤링 (★ 미래 참조 금지)
│   ├── train.py           # 시간순 split 학습 + 비용 기반 임계값
│   └── download_data.py   # UCI 데이터 자동 다운로드
├── analysis/              # a1~a7 분석 스크립트 (각각 독립 실행 가능)
├── app/streamlit_app.py   # 대시보드
├── data/
│   ├── history/           # 일별 수집 CSV (git에 커밋됨)
│   └── raw/               # UCI 원본 (gitignore, 스크립트로 재현)
├── models/                # metrics.json, 예측 결과, 변수 중요도
├── reports/analysis_report.md
└── outputs/               # 실행 로그
```

## 실행 방법

```bash
git clone https://github.com/<본인계정>/predictive-maintenance-portfolio
cd predictive-maintenance-portfolio
pip install -r requirements.txt

python src/download_data.py              # UCI 데이터 받기
python src/collector.py --minutes 1440   # 센서 24시간 치 수집
python src/build_db.py                   # CSV → SQLite
python src/train.py                      # 학습 + 성능 리포트

cd analysis && python a1_pipeline.py     # 분석은 a1~a7 순서로
streamlit run app/streamlit_app.py       # 대시보드
```

전부 **무료**입니다. 클라우드 계정도, 신용카드도 필요 없습니다.

## 한계와 가정

<!-- ★★ 이 섹션을 절대 지우지 마세요. 채용 담당자가 먼저 보는 곳입니다. -->

- **시뮬레이터 데이터는 합성입니다.** 성능 수치를 실제 설비에 그대로 적용할 수 없습니다.
  이 프로젝트의 결과물은 성능이 아니라 **파이프라인 설계와 검증 방법**입니다.
- **시뮬레이터의 고장 규칙은 결정론적**이라 실제 설비보다 예측이 쉽습니다.
  그래서 실데이터(AI4I·SECOM)를 함께 분석했습니다.
- **비용 가정(800만원 : 30만원 = 26:1)은 추정치입니다.** 실제로는 정비팀에서 받아야 합니다.
  비용비가 바뀌면 최적 임계값도 바뀝니다(민감도 분석 포함).
- **SECOM은 예측에 실패했습니다**(PR-AUC 0.083, 기준선 0.061).
  억지로 올리지 않고 실패 원인(효과크기 0.32, 불량 104건, 공정 분포 이동 92%)을 규명했습니다.
- **AI4I 라벨에 모순이 있습니다.** RNF 19건 중 18건이 `Machine failure=0`입니다.
  원본 정의를 그대로 두고 분석했으며, 이 특이점을 리포트에 명시했습니다.
- 14일치 데이터라 **계절성·장기 열화**를 반영하지 못합니다.
- 상관은 인과가 아닙니다. "토크를 낮추면 고장이 준다"고 말할 수 없습니다.

## 무엇을 배웠나

1. **정확도를 쓰지 않는 법.** 불균형에서는 PR-AUC와 기준선 대비로 봅니다.
2. **누수는 데이터가 아니라 문제 정의에서 생깁니다.** 같은 데이터라도
   '감지'로 풀면 누수가 안 보이고 '예지'로 풀면 22.6%가 날아갑니다.
3. **안 되는 걸 안 된다고 쓰는 것.** SECOM에서 성능을 못 냈고, 그 이유를 규명했습니다.
   이게 데이터를 바꿔서 좋아 보이게 만드는 것보다 낫다고 판단했습니다.
